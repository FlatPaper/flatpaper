Part 1 · Install and use
1.1

Install it

flatpaper is a Claude Code plugin loaded from a local clone. Pick one way to load it.

For the CLI only, alias it. Edits take effect on the next session.

alias claude='claude --plugin-dir ~/Documents/GitHub/flatpaper'

For the CLI, the IDE extension, and the desktop app, install it:

claude plugin marketplace add ~/Documents/GitHub/flatpaper
claude plugin install flatpaper-stack@flatpaper-stack --scope user
claude plugin update flatpaper-stack@flatpaper-stack   # after edits; bump the version first
/reload-plugins                            # in an open session

Then add these to ~/.claude/settings.json and restart Claude Code. A session that is already open keeps its old tool list.

{
  "env": { "CLAUDE_CODE_ENABLE_TODO_TOOLS": "1" },
  "attribution": { "commit": "", "pr": "", "sessionUrl": false }
}
SettingNeededWhy
CLAUDE_CODE_ENABLE_TODO_TOOLSYesflatpaper-mode puts each playbook step in the task list. Without it, the mode keeps a checklist in its replies instead.
attributionNoRemoves the Claude co-author line from commits and PRs. Claude Code enforces it, so the model has nothing to remember.
gh, jqOptionalgh reads PRs back; without it, the read-back is reported inconclusive. Both check the latest release for the drift line; without them, it still counts commits.
1.2

Use it

Quick questions need nothing. For real work, start with the mode and give up to five parts, one sentence each.

/flatpaper-stack:flatpaper-mode <goal>. done means <check>. show me <proof>. <what you know>. <constraints>.
PartExample
Goalfix the csv export dropping its last row
Done checkdone means the 60k-row fixture exports every row
Proofshow me row counts before and after
What you knowstarted after yesterday's deploy. failing job is 4812
Constraintsrepro first. no PR. don't touch the schema

Only the goal is required. A missing part gets proposed back to you in one line. The words in your goal pick the playbook ("fix" picks Bug fix, "how does" picks Investigation). Stay in the same session for follow-ups: each prompt is matched again, so review, then fix, then PR just works.

Stepping away? Say so, and the mode decides and logs reversible calls instead of asking:

/flatpaper-stack:flatpaper-mode im stepping away. <goal>. done means <check>. keep a decision log.

Coming back? /flatpaper-stack:ketchup for what changed, /flatpaper-stack:show-me-your-work catch me up for the decision log. Every command is in Part 3.
