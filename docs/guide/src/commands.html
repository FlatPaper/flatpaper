3.3

Every skill

Skills tagged by hand never start on their own; you type them, or a playbook step asks you first. The rest also run from playbook steps.

/flatpaper:flatpaper-mode by hand

Rigorous mode. Matches a playbook (table above) and drives it to verified work.

/flatpaper:flatpaper-mode <goal>. done means <check>. show me <proof>. <what you know>. <constraints>.

/flatpaper:sharpen by hand

For a task you can't state crisply. It frames the task the way an expert would, then does it.

/flatpaper:sharpen write onboarding docs for the billing service
/flatpaper:sharpen figure out why our nightly job got slower this month

/flatpaper:ketchup by hand

What changed since your last message, in under 150 words, and what needs you.

/flatpaper:ketchup

/flatpaper:show-me-your-work

Starts or reads a decision log. Loads on its own for autonomous and multi-phase runs. Read the Attention section first.

/flatpaper:show-me-your-work keep a decision log for this migration
/flatpaper:show-me-your-work catch me up on what you did
column -s$'\t' -t decisions.tsv          # read the log in a terminal

/flatpaper:recall by hand

A current-state brief across this project's recent sessions, logs, and PRs. Defaults to the last 7 days.

/flatpaper:recall
/flatpaper:recall my work on the export cache this week

/flatpaper:why

Why code is the way it is, from git, PRs, and any trackers, docs, or chat the session can reach. Every claim gets a confidence tier.

/flatpaper:why does the uploader retry exactly 3 times?
/flatpaper:why did we pick postgres advisory locks over redis?

/flatpaper:architect

Competing design sketches before code. Add "with checkpoint" to review the sketch before it implements.

/flatpaper:architect a plugin system for export formats
/flatpaper:architect with checkpoint the new auth session store

/flatpaper:arena

Three candidates on one task, a judge, a base, and grafts.

/flatpaper:arena the landing page hero copy
/flatpaper:arena a parser for the legacy fixed-width format

/flatpaper:interrogate

Three fresh reviewers try to break a change, then one verdict. Applies no fixes.

/flatpaper:interrogate the diff on this branch
/flatpaper:interrogate src/sync/ before I open the PR

/flatpaper:no-comments

Runs on its own before a PR is pushed. A fresh comment-sicko agent strips comments that narrate or excuse code, and flags code that only makes sense with a comment. The flags get fixed. A "do not remove" comment becomes a type, test, or lint if you approve.

/flatpaper:no-comments
/flatpaper:no-comments src/billing/

/flatpaper:swarm

Parallel workers over slices or a race, one table back.

/flatpaper:swarm check every test file for tests that pass when the code does nothing
/flatpaper:swarm race 3 workers on fixing the flaky upload test, first pass wins

/flatpaper:unslop

Cuts AI tells from prose. Runs on every flatpaper-mode reply.

/flatpaper:unslop the release notes in CHANGELOG.md

/flatpaper:technical-writing

The writing standard for docs, READMEs, PR bodies, and commit messages.

/flatpaper:technical-writing rewrite docs/setup.md as a how-to

/flatpaper:blast-radius

What a change breaks outside its diff, with a rerunnable proof of the one safety fact. Takes a PR, a branch, or a diff; defaults to the current branch.

/flatpaper:blast-radius PR 123
/flatpaper:blast-radius

/flatpaper:create-verification-skill by hand

Once per repo. Generates and proves .claude/skills/verify-<app>/.

/flatpaper:create-verification-skill

/flatpaper:maintain-verification-skill by hand

Rechecks every feature in the map from source and live. Ends clean, changed (one PR), or blocked.

/flatpaper:maintain-verification-skill

To run it on a schedule, ask /schedule for a recurring cloud agent that runs it.

/flatpaper:correct by hand

When you've corrected the same mistake twice. Makes it impossible and shows the check failing on it.

/flatpaper:correct
/flatpaper:correct agents keep importing from internal/ directly

/flatpaper:reflect by hand

At the end of a long session. Proposes skill, CLAUDE.md, and memory edits for your approval.

/flatpaper:reflect
3.4

Steering a run

Steering prompts are one line. Name the principle or the rule that was broken. The agent must say which decision the principle changed.

apply prove it works. show me the real output, not the build log.
apply fix root causes. that guard silences the symptom.
apply attack the premise. both fixes assumed the cache is stale.
apply build the lever. write the script instead of editing by hand.
apply subtract before you add.
i said repro first. i did not ask for a fix yet. stay on the bug fix playbook.
new task: review the open PR.

All principle names live in skills/flatpaper-mode/references/principles.md: laziness protocol, foundational thinking, redesign from first principles, attack the premise, subtract before you add, minimize reader load, outcome-oriented execution, experience first, exhaust the design space, build the lever, model the domain, boundary discipline, type system discipline, make operations idempotent, migrate callers then delete legacy APIs, separate before serializing shared state, prove it works, fix root causes, sequence verifiable units, test behavior not implementation, explain the number, guard the context window, never block on the human, encode lessons in structure.

3.6

Pitfalls

  • Naming skills in the prompt. "investigate, then prototype, then build" reorders steps the playbook already sequences. State the goal and constraints.
  • Leading with your theory. The agent searches where you point. Give the fact ("/ws returns 403"), not the "so..." after it.
  • A done check that can't fail. "see if there's a way" or "work for an hour" lets anything count as done.
  • Parallel agents in one worktree. They overwrite each other. Say "own worktree per attempt".
  • Looping before you trust the loop. Get a verification skill working first.
  • Correcting by hand. A correction in chat helps one run. Use /flatpaper:correct.
  • Editing a skill mid-task. Note the problem and fix the skill in its own change.
