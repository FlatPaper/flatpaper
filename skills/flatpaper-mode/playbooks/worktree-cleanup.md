### Worktree cleanup

**You own the disk and the safety gate.** Remove merged or abandoned git worktrees to reclaim space. Removal can lose work, so every step guards against removing something in use or holding uncommitted changes.

1. Snapshot and audit. Record `df -h .`, then run `scripts/worktree-audit.sh` from this skill's base directory (shown when the skill loads) inside the repo, or pass the repo path. It reads paths from `git worktree list --porcelain`, never hand-typed ones, and it also lists stray directories under `.claude/worktrees/`, where Claude Code keeps its own worktrees. It is read-only and takes no git locks. Check that every worktree in `git worktree list` has a row, and that you read the `note:` lines for anything the script skipped.
2. The bucket is advice, not permission. Ask the user which sessions and worktrees are still in use, and cross-check every candidate against that set. The user's answer wins over the script. Check that each `safe` row is either confirmed unused by the user or moved to held.
3. Verify recent use. A `verify-recent` row means a Claude Code transcript from the last 24 hours ran in or touched that path. `LAST_SEEN` shows when and the first 8 characters of its session id. Pass `--self <this session id>` so this audit's own reads are left out. For other sessions, send a subagent to read those transcripts and report whether the session is still going and which worktrees it uses. Check that every `verify-recent` row is marked in use or not in use, with the session id.
4. Pause on lost work. `wip:N` is N files with uncommitted tracked changes. Show `git -C <path> status` and `git -C <path> diff --stat`, and get a decision for each. `untracked:N` files are gone after removal too, so name them. Clean, merged, and not in use can proceed once the user confirms the list. Check that no `hold-wip` or `hold-open-pr` row is in the removal set without an explicit yes from the user for that path.
5. Remove the confirmed set. Only after the user confirms the list, run `git worktree remove <path>` per path. Never pass `--force` on a worktree with uncommitted tracked changes. For an `untracked:N` row, pass `--force` only after the user has seen the file names and said yes for that path. If git refuses, stop on that path and report why. For a `prunable` row, run `git worktree prune --dry-run --verbose`, show what it would drop (it is global, not per path), and run `git worktree prune` only after the user confirms that whole list. A stray directory under `.claude/worktrees/` is not a registered worktree, so git cannot remove it. Show what it holds and ask before deleting it. Branch refs survive removal, so committed work is not lost. Check that `git worktree list` no longer shows the removed paths, and `df -h .` is recorded again.

This playbook removes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h .` before and after, the worktrees removed, and a one-line reason for each one held back (in use by which session, open PR, or uncommitted work).
