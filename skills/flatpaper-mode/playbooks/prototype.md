### Prototype

**You own the decision, not the code.** The prototype is throwaway. The real build follows Feature.

Speed over polish. The rigor is in settling the question cheaply.

1. Name the decision the prototype exists to make. No decision means no prototype. Route to Feature.
2. Build in a scratch directory, separate from production code. Use the smallest script or page that exercises the question. No tests, no abstractions.
3. When comparing options, run each one the same way and label the results. Propose an option the user didn't ask for when it's worth seeing.
4. Observe the thing being decided: the output, the timing, the screenshot, the failure. The observation is the test.
5. Recommend one option with its evidence.

**Reply:** the options tried, the evidence for each, tradeoffs, your recommendation, and the scratch path. Say plainly that the prototype is throwaway.
